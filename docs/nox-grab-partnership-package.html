One-Page Partnership Brief

Prepared for Grab Partnerships · Target: partnerapp.partnerships@grabtaxi.com · Date: November 2026

The Pitch

NOX is Urban Entertainment Infrastructure — a nightlife operating system covering event discovery, digital ticketing, venue and promoter tools, QR entry validation, and payments. We are launching in Yangon, Myanmar, with ASEAN expansion planned. We want NOX to live inside Grab as a Partner App: the evening category Grab does not yet own, delivered through the surface users already open.

The Problem

  • Grab's Myanmar and ASEAN users spend evenings out — food, rides, socializing — but Grab has no native nightlife or events surface.
  • Existing ticketing options in Yangon are fragmented: paper, cash, Facebook posts, promoter WhatsApp groups. No trusted digital layer.
  • The "how do I get there" gap is unsolved: people find an event, then separately hail a ride. Two apps, two payments, zero data connection.

The Proposal

A NOX Partner App embedded in the Grab SuperApp webview. Users discover events near them, book with GrabPay, earn GrabCoins, and get a one-tap Grab ride to the venue — all without leaving Grab. NOX owns tickets, entry validation, and the venue graph. Grab owns distribution, identity, payments, and mobility.

  1. Contextual entry: "Tonight" / "Events near you" placement, post-ride and post-food prompts.
  2. Location-aware discovery powered by Grab location + NOX venue graph.
  3. Checkout via GrabPay (dual-rail fallback: KBZPay / WavePay where GrabPay coverage is incomplete).
  4. GrabCoins on successful purchase; SuperApp analytics events for funnel visibility.
  5. Post-purchase in-app ride prompt to the venue.
  6. Arrival: NOX Flutter scanner validates the cryptographically protected QR. NOX-owned, server-side authoritative.

Mutual Value

For Grab

  • A high-intent evening category that drives rides, GMV, and GrabCoins loops.
  • Entertainment behavioral data (with consent) improves evening mobility predictions.
  • Differentiation in Myanmar and ASEAN without building nightlife ops in-house.

For NOX

  • Instant access to Grab's user base with zero separate acquisition cost for that channel.
  • Trusted identity and payments already solved.
  • Ride integration closes the last-mile gap pure ticketing apps leave open.
  • Credibility for venue and promoter conversations.

Technical Adapter Sketch

NestJS adapters on the existing NOX backend (Turborepo monorepo: Flutter consumer, Next.js dashboards, NestJS services, Supabase/PostgreSQL, Redis). Four new adapter modules. Existing RLS, audit logging, and rate limiting unchanged.

Four Adapters

01 · GrabIdentityAdapter

OAuth 2.0 + PKCE via SuperApp SDK IdentityModule. No separate NOX login inside the webview. Create-on-first-use: map Grab user to NOX identity with explicit consent. Store only the minimum GrabID reference needed for reconciliation.

// apps/api/src/adapters/grab/grab-identity.adapter.ts
export interface GrabIdentityPort {
  exchangeCode(code: string, codeVerifier: string): Promise<GrabIdToken>;
  getProfile(accessToken: string): Promise<GrabUserProfile>;
  provisionNoxUser(grabUser: GrabUserProfile): Promise<NoxUser>;
}

export interface GrabUserProfile {
  grabUserId: string;
  phoneHash?: string;   // hashed only, never raw
  displayName?: string;
  locale?: string;
}

export interface NoxUser {
  id: string;
  grabUserId: string;
  createdAt: Date;
  consentVersion: string;
}

02 · GrabPayAdapter

HMAC-verified webhooks. Idempotent capture-to-ticket state machine: webhook delivery is at-least-once, so every transition is keyed on a deterministic idempotency key derived from the Grab payment reference. Ticket issuance happens server-side only after confirmed capture — never from the client.

// apps/api/src/adapters/grab/grab-pay.adapter.ts
export interface GrabPayPort {
  createPayment(req: CreateGrabPaymentRequest): Promise<GrabPaymentIntent>;
  handleWebhook(rawBody: Buffer, signature: string): Promise<void>;
  refund(grabPaymentRef: string, amount: number): Promise<void>;
}

export type TicketState |
  | 'pending_payment'
  | 'captured'
  | 'issued'
  | 'refunded'
  | 'voided';

export interface CreateGrabPaymentRequest {
  orderId: string;
  amountMinor: number;   // currency minor units
  currency: string;
  description: string;
  returnUrl: string;    // in-webview return
  metadata: Record<string, string>;
}

State machine rules: captured → issued is the only forward path that mints a QR. issued → refunded invalidates the QR server-side and pushes a revocation to the venue scanner fleet. Duplicate webhook deliveries are no-ops after the first successful transition.

03 · GrabAnalyticsAdapter

Maps the NOX funnel to SuperApp analytics events so Grab sees session depth, not just a link click. Events fire from the webview via the SuperApp SDK analytics bridge where available.

// apps/api/src/adapters/grab/grab-analytics.adapter.ts
export interface GrabAnalyticsPort {
  track(event: GrabAnalyticsEvent): Promise<void>;
}

export interface GrabAnalyticsEvent {
  name: 'nox_discover_view' | 'nox_event_view'
         | 'nox_checkout_start' | 'nox_payment_success'
         | 'nox_ride_prompt_shown' | 'nox_ride_booked'
         | 'nox_entry_validated';
  grabUserId: string;
  properties: Record<string, unknown>;
  timestamp: string;  // ISO-8601
}

04 · GrabRideHandoffAdapter

Post-purchase in-app ride prompt. Stays Grab-native — no external ride-hailing promotion, per Partner App constraints. Deep-link or Farefeed-style handoff inside the webview.

// apps/api/src/adapters/grab/grab-ride-handoff.adapter.ts
export interface GrabRideHandoffPort {
  buildRidePrompt(input: RidePromptInput): RidePrompt;
}

export interface RidePromptInput {
  venueLat: number;
  venueLng: number;
  venueName: string;
  eventStart: Date;
  grabUserId: string;
}

export interface RidePrompt {
  deeplink: string;   // grab:// or https://grab.onelink.me/...
  headline: string;
  subline: string;
  suggestedPickupWindow: { from: Date; to: Date };
}

Booking Flow — Sequence

User (in Grab) → SuperApp Webview → NOX Partner App (Next.js) │ ├─1─ GET /nox/events?near=grab_location │ ← venue graph + event list (RLS-scoped) │ ├─2─ GET /nox/events/:id │ ← event detail, ticket tiers, prices │ ├─3─ POST /nox/orders { eventId, tierId, qty } │ → order created (status: pending_payment) │ → GrabPayAdapter.createPayment() │ ← GrabPaymentIntent { paymentUrl, grabRef } │ ├─4─ Webview redirects to GrabPay (in-container) │ User confirms with GrabPin / biometrics │ ├─5─ GrabPay webhook → GrabPayAdapter.handleWebhook() │ HMAC verify → idempotent transition │ pending_payment → captured → issued │ Ticket minted server-side, QR generated │ (cryptographically signed, venue-scoped) │ ├─6─ Webview shows confirmation + GrabRideHandoffAdapter │ buildRidePrompt(venue, eventStart) │ ← deeplink + suggested pickup window │ GrabAnalyticsAdapter.track('nox_ride_prompt_shown') │ ├─7─ (Optional) User taps → Grab ride booked │ GrabAnalyticsAdapter.track('nox_ride_booked') │ └─8─ Arrival: NOX Flutter scanner (venue app) validates QR signature + server revocation list GrabAnalyticsAdapter.track('nox_entry_validated')
